# SocketLens v0.1.0-alpha Release Notes

These notes are the source text for the `v0.1.0-alpha` GitHub Release.

## GitHub Release Title

SocketLens v0.1.0-alpha

## GitHub Release Body

SocketLens `v0.1.0-alpha` is the first public alpha release candidate for the project.

SocketLens is a local-first desktop WebSocket debugger for developers building realtime applications. This alpha is usable for guided demo workflows, direct WebSocket debugging, local echo-server testing, session files, and native proxy testing, while remaining under active development before a stable `1.0` release.

### Current Status

- Alpha quality: useful for local evaluation, demos, and focused contributor testing.
- Source-first setup: `npm install` and `npm run dev` are the primary path for new users.
- Release-freeze mode: new work is limited to blockers, bug fixes, onboarding, docs, CI/release, privacy/security wording, and small clarity fixes.
- License: GNU Affero General Public License v3.0 only (`AGPL-3.0-only`).
- Native desktop/proxy workflows require Rust `1.77.2` or newer, Cargo, and Tauri prerequisites.
- Downloadable desktop artifacts are expected only after the release workflow succeeds for the tag.
- No telemetry, hosted sync, account system, cloud backend, or paid service is included.

### Highlights

- Guided Investor Demo Mode with offline synthetic auth, chat, heartbeat, notification, error, replay, and AI-explain demo examples.
- Direct WebSocket mode for connecting to `ws://` and `wss://` endpoints from inside SocketLens.
- Manual send and packet replay for active direct connections.
- Native Rust proxy MVP for local client-to-target WebSocket forwarding and captured frame events.
- Virtualized packet timeline with search, filters, direction indicators, status badges, packet size, retention controls, auto-scroll, and clear behavior.
- Payload inspector with Pretty, Raw, and Metadata tabs.
- Session save/load and packet import/export as local JSON files.
- Settings for theme, compact mode, auto-scroll, packet retention, language, privacy, and optional AI provider configuration.
- Russian UI by default with English fallback and instant persisted language switching.
- Optional AI analysis architecture for OpenAI-compatible endpoints and Ollama, disabled by default.
- Local examples: TypeScript WebSocket echo server and browser chat demo.
- Public launch documentation, CI, release workflow, security/privacy docs, issue templates, and contributor guide.

### Install And Run

```bash
git clone https://github.com/socketlens/socketlens.git
cd socketlens
npm install
npm run dev
```

Open:

```text
http://127.0.0.1:1420
```

The UI opens in Russian by default. Use Settings -> Language to switch to English.

### Echo Server

```bash
npm run dev:echo
```

The echo server listens on:

```text
ws://127.0.0.1:17787
```

Use Direct Mode in SocketLens to connect to that URL.

### Native Desktop And Proxy Mode

```bash
npm run dev:desktop
```

Proxy mode requires the native Tauri desktop app, Rust `1.77.2` or newer, Cargo, and platform-specific Tauri prerequisites.

### Downloads

Unsigned desktop artifacts are produced by the GitHub release workflow when it runs successfully for this tag. If artifacts are not attached yet, build from source using the commands above.

Expected artifact families:

- Windows: `.msi` or `.exe`
- macOS: `.dmg` or `.app`
- Linux: `.AppImage`, `.deb`, or `.rpm`

Operating systems may show unidentified-developer warnings until code signing is configured.

- `cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml`

- Proxy mode smoke test in the native desktop app

### Known Limitations

- SocketLens is alpha software and does not provide stable `1.0` compatibility guarantees.
- Desktop release artifacts are unsigned until signing is configured.
- Proxy mode is an MVP focused on local development and should be tested carefully before relying on it for complex external clients.
- Browser development mode cannot run native proxy functionality; use `npm run dev:desktop`.
- Canonical brand SVG assets are included under `docs/assets/branding`; native installer icon regeneration still needs stable-release validation.
- AI is optional, disabled by default, and only works after a user configures an OpenAI-compatible or Ollama provider.
- No telemetry, hosted sync, team workspace, or revenue-generating service is included in this release.
