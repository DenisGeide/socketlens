# v1.0.0-alpha Freeze Report

This document freezes the scope for SocketLens `v1.0.0-alpha`.

The goal is to reduce release risk, keep the alpha focused, and avoid turning the first public launch into a moving target.

## Freeze Decision

SocketLens is now in `v1.0.0-alpha` stabilization mode.

Allowed before release:

- release blockers,
- bug fixes,
- onboarding clarity fixes,
- documentation corrections,
- privacy/security wording fixes,
- CI/release script fixes,
- small UI clarity fixes that do not introduce new workflows.

Not allowed before release:

- new product modes,
- new AI capabilities,
- account/cloud/team features,
- telemetry,
- billing or pricing work,
- broad proxy architecture changes,
- large visual redesigns,
- large refactors that do not fix a release blocker.

## Current Honest Status

Source-first alpha readiness is close. The npm workspace path is reproducible and the app has a runnable first-run demo, local echo server workflow, Direct Mode, replay, filters, environments, Socket.IO/GraphQL WS decoding foundations, session files with redacted export, settings, i18n, optional AI settings, diagnostics, docs, tests, CI, and release metadata.

Native release readiness is not fully frozen until Rust/Cargo checks and platform Tauri builds are validated on machines with the required toolchain.

## Release Blockers

### Source Alpha

No source-alpha release blockers are known after the final README/manual-QA documentation pass and the available npm checks pass.

### Native Downloadable Artifacts

These block attaching public native artifacts:

- `cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml` must pass on a machine with Cargo installed.
- `apps/desktop/src-tauri/Cargo.lock` must stay committed for native reproducibility.
- `npm run release:build` must pass on the target platform or in GitHub Actions.
- Windows, macOS, and Linux artifacts are unsigned; release notes must keep the warning visible.
- Native Proxy Mode must be smoke-tested in `npm run dev:desktop` before claiming proxy artifact readiness.

## Unfinished Systems

These are acceptable alpha limitations, not reasons to expand scope before release:

- Proxy Mode is a local-development MVP, not a production traffic gateway.
- AI Explain is optional, disabled by default, provider-dependent, and not part of the core debugger requirement.
- Public screenshots are captured from real implemented states. The canonical GIF should still be recorded from a real app run before embedding it in public launch posts.
- Native app icons exist for release metadata but should be regenerated from the canonical brand SVG before a stable release.
- Session exports are local JSON and include redaction support for exported copies; users still need to review files before sharing.
- API keys are stored locally through existing settings storage, not an OS keychain.
- Runtime remote plugins and marketplace-style plugin loading are not implemented.
- MessagePack, BSON, and Protobuf are roadmap/foundation work, not supported user-facing decoders yet.

## Unstable Or High-Risk Systems

Treat these areas as bug-fix-only until after `v1.0.0-alpha`:

- `apps/desktop/src/store/connection-store.ts`: Direct WebSocket lifecycle, replay, recent connections, and cleanup are coupled in a large store.
- `apps/desktop/src-tauri/src/proxy.rs`: native proxy lifecycle is the highest backend risk and needs platform testing.
- `apps/desktop/src/App.tsx`: central orchestration is large and should not receive broad feature work during freeze.
- `apps/desktop/src/components/sidebar.tsx`: connection UI, demo controls, proxy/direct choices, and first-run actions are dense.
- `apps/desktop/src/components/settings-page.tsx`: settings, AI provider UI, privacy copy, and persistence are dense.
- `apps/desktop/src/demo/investor-demo.ts`: demo quality is important, but packet story changes should stop unless fixing confusion.

## Risky TODOs Or Placeholder Claims

No dangerous `TODO`, `FIXME`, or `HACK` markers are expected in release-critical app/source paths.

The remaining placeholder-related matches are expected:

- input placeholders,
- translation placeholder keys,
- clearly labeled offline demo AI explanation,
- source-level MessagePack/BSON decoder stubs that are explicitly unregistered and documented as not implemented,
- documentation that explicitly warns against fake screenshots or fake production traffic.

Do not add placeholder-only product behavior during freeze.

## Unnecessary Complexity To Avoid Before Release

Do not simplify these with broad refactors during freeze unless a release blocker appears:

- splitting large stores/components,
- reworking the i18n structure,
- changing session file format,
- changing proxy backend architecture,
- introducing new state libraries or service layers,
- replacing the AI provider abstraction,
- redesigning the layout.

These may be good post-alpha maintainability tasks, but they are not freeze work.

## Code Smells To Track After Release

- Several frontend files are large enough to slow contributor onboarding.
- Direct connection lifecycle and replay behavior are tightly coupled.
- Proxy Mode needs more automated coverage and native lifecycle tests.
- The i18n JSON files are large and flat; manageable for alpha, but future languages may need namespace tooling.
- Release docs mention native artifacts, but artifact trust still depends on successful GitHub Actions runs and unsigned-artifact warnings.

## Stability Priorities

Before tagging:

1. Keep `npm run check` green.
2. Keep `npm run release:prepare` green.
3. Smoke-test Investor Demo Mode from clean local state.
4. Run `npm run dev:echo`.
5. Connect Direct Mode to `ws://127.0.0.1:17787`.
6. Send and replay `{ "command": "ping" }`.
7. Verify packet selection updates the inspector.
8. Verify filters, smart filters, grouping, bookmarks, notes, and tags.
9. Verify Settings language/theme/packet limit/environment persistence.
10. Verify AI disabled state does not block core workflows.
11. Verify session save/load/export/redaction in browser fallback and native mode where available.
12. Verify diagnostics copy/export excludes sensitive payloads by default.
13. On a Cargo-enabled machine, run native checks and proxy smoke tests.

## Freeze QA Commands

Run from the repository root:

```bash
npm install
npm run check
npm run release:prepare
```

On a machine with Rust and Cargo:

```bash
cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
npm run dev:desktop
npm run release:build
```

## Definition Of Alpha Ready

SocketLens is `v1.0.0-alpha` ready when:

- a new developer can run `npm install` and `npm run dev`,
- Investor Demo Mode works from a clean first launch,
- the local echo server works with Direct Mode,
- manual send and replay work against `ws://127.0.0.1:17787`,
- packet timeline, filters, grouping, and inspector remain stable,
- sessions export/import and redaction behave predictably,
- Socket.IO demo traffic is decoded without breaking raw WebSocket mode,
- environments resolve locally without logging secrets,
- diagnostics are useful for bug reports and exclude sensitive payloads by default,
- docs match package scripts,
- privacy/AI behavior is clearly described,
- no fake production claims exist,
- CI passes,
- native artifact limitations are stated honestly.

Downloadable artifact readiness additionally requires successful native checks and platform builds.
